# 视频测试使用方法（video_test.py）

> 在 PC 上把 OpenMV 录的现场视频离线跑一遍**主脚本的识别管线**，看"哪些帧识别上了 / 哪帧丢了目标 / 什么时候切档 / 飞控收到的坐标是多少"，改识别参数不用反复烧录 OpenMV。
> 配套说明：[主脚本识别说明.md](主脚本识别说明.md)（主脚本怎么识别的）；脚本 [video_test.py](video_test.py)。

## 组成文件

| 文件 | 作用 |
|---|---|
| `video_test.py` | 视频测试脚本。识别参数 + 算法 1:1 来自主脚本 `Guidance_vision_scrpit.py` |
| `convert_mjpeg.py` | 把 OpenMV 录的 `.mjpeg` 转成 `.mp4`（OpenMV 的 mjpeg 没有播放索引，必须转才能正常播放/定位） |

## 依赖

- Python 3 + `pip install opencv-python numpy`
- FFmpeg（`convert_mjpeg.py` 转换用，装好后 `ffmpeg` 要能在命令行直接敲出来）

## 三步用法

1. **录视频**：OpenMV 端主脚本 SD 卡挂载后自动开录（`DEBUG_AUTO_RECORD=True`），或飞控发 0x03 命令开录。录完把 SD 卡上的 `record_*.mjpeg` 和 `log_*.txt` 一起拷到电脑。
2. **转 mp4**：
   - 单个：`python convert_mjpeg.py record_1.mjpeg`
   - 整个目录：`python convert_mjpeg.py --dir 目录`
   - 保留原文件：加 `--keep-original`
3. **跑视频测试**：
   - `python video_test.py record_1.mp4`（指定文件）
   - 不带参数默认跑 `led.mp4`

## 界面怎么看

- **锁定目标**：内圈红 + 外圈青双圆
- **被拒 blob**：灰圆 + 一个字母，这就是"为什么没识别到"的直接原因：
  - `R`=圆度不够　`D`=密度不对　`L`=亮度超界　`A`=色度 a 不够绿　`S`=结构化采样不满足（既不是 SOLID 也不是 HALO）
- **绿框** = ROI 搜索窗（锁定后只在预测位置附近搜）
- **采样点**：中心 5 点 + 外环 4 点，颜色=分类（绿=是绿、白=过曝白核、品红=干扰色、灰=未分类）
- **pattern 标签**：SOLID（青）/ HALO（黄）——近距过曝时大概率显示 HALO
- **橙色箭头**：跟踪速度矢量（预测下一帧去哪）
- **左上 HUD**：
  - 第一行：`tier` 当前档 / `cand` 候选数 / `fps`
  - 第二行：`pattern` / `px` 像素数 / `dist` 估算距离 cm
  - 第三行：`xout yout`（**飞控实际收到的坐标**）/ `frame` 帧号
- 每帧终端也会打印一行同样的信息，末尾带切档提示（`switch->MID` 等）

## 键盘

| 键 | 功能 |
|---|---|
| SPACE | 暂停 / 继续 |
| n | 暂停时单步一帧 |
| r | 重置跟踪状态 |
| z | 放大 / 原尺寸切换 |
| q / ESC | 退出 |

## 常见问题

- **报 video not found**：路径写错，或忘了把 `.mjpeg` 转成 `.mp4`。
- **convert_mjpeg 报找不到 FFmpeg**：装 FFmpeg 并加入系统 PATH（脚本顶部注释有常见安装路径说明）。
- **画面识别结果和实机有小出入**：正常。OpenMV 的 LAB 和 OpenCV 的 LAB 换算公式不同（OpenMV 近似快算、OpenCV CIE 标准），阈值附近的 blob 会有差异。这个工具是"还原个大概、看哪些帧出问题"，最终以实机为准。
- **视频不是 240×320**：脚本会自动缩放，保证三档像素范围语义与硬件一致；但最好直接用主脚本录的原始视频，不要用手机拍的（纵横比、颜色空间都对不上）。

## 参数同步（重要）

`video_test.py` 头部的 `DIST_TIERS`、`FRAME_*` 等参数是**从主脚本照抄**的（2026-08-07 已全部对齐）。以后改了主脚本参数，用对比工具 diff 两个文件头部参数区同步即可——**识别算法部分两边结构一样，不用动**。
